# Public 1.1 Operations Upgrade

## Approved Scope

Implement the user's selected workbench, interactive calendar, refunds/receipt history, confirmation sharing, quick booking and interaction refinements. Remain offline. Preserve data keys, package identity, signing key and non-blocking turnaround warnings. No temporary holds, cloud sync, equipment inventory or SQLite migration in this release.

## Architecture

Keep existing app.js atomic data mutations and normalization as the authority. Add operations.js and operations.css for the workbench, booking wizard and calendar interaction. Add confirmation.js for local PNG rendering and sharing through the existing Capacitor bridge. Keep financial normalization and ledger calculations in app.js to ensure import, reload, totals and UI agree.

## Tasks

- [x] Financial records: positive receipt/refund amounts in integer-cent calculations; refunds reference a valid receipt and cannot exceed unrefunded value; date/reason validation; audited void instead of physical deletion. Old income records normalize as receipts. Validate linked records during imports and preserve newer financial state on safe duplicate merge. Test cancellation, overrefund, concurrent refund, rounding, storage rollback and reload.
- [x] Workbench: current/next session, ending soon, pending orders, outstanding balances and turnaround reminders; explicit detail/collect/new-booking buttons. Refresh when visible and after state changes.
- [x] Calendar: day/week and scene filter, available-slot buttons obeying configured step/min duration/shared spaces/closed dates. Prefill wizard without saving; final save must still use atomic conflict checks. Keep explicit previous/next buttons and swipe.
- [x] Wizard: schedule/customer/quote steps plus persisted quick-entry mode. Validate before advancing; route validation errors to visible step; guard abandonment and keep drafts on tab changes. Make state labels and explicit destructive actions visible.
- [x] Confirmation: branded local PNG preview; customer/contact privacy opt-in; clear pending/cancelled states and financial summary; share via native filesystem/share bridge or web share/download fallback. Handle long text, image load failures, cancel and native back.
- [x] Settings: direct profile/scenes/rules entry points; distinct backup and about groups, preserve unsaved config guard.
- [x] Verification: node --test tests/*.test.js; browser flows at 320, 390 and 1280 widths; file:// cold start; original backup migration; build signed Android APK; verify asset hashes/signature/no INTERNET permission.
- [ ] Release: version 1.1.0/code 4, manuals/guide/changelog and download links, new APK/ZIP, commit and non-force push, download/hash check.

## Acceptance Examples

- Receipt 200, refund 50 => gross 200/refund 50/net 150; a further refund 151 fails without changing storage.
- Voiding a receipt with active refunds fails; void refund first. Voided records remain visible and do not count in totals.
- Adjacent 10:00-12:00 and 12:00-14:00 bookings succeed with a visible reminder; 11:30-13:30 fails.
- Selecting a free slot only pre-fills a form; no order exists until explicit final submission.
- New runtime assets are in Android, service-worker and ZIP allowlists. Old public APK signature is unchanged for upgrade compatibility.
